# UI 设计系统与界面规范

**状态**：现行规范（2026-09-18）  
**适用**：`desk-pet` 全部界面（设置、聊天、侧边栏、桌宠窗、安装器 UI）  
**背景**：界面大量沿用第三方 Cyrene-Agent 的结构与文案，**不是**我们已规划好的原创设计系统。本文是后续 UI 的统一依据；已开发部分按 §8 渐进收束。

## 2. 现状诊断（为什么需要规范）

| 问题 | 现状 |
|---|---|
| 品牌残留 | `package.json` name=`live2d-cyrene`，`electron-builder` productName=`Cyrene`，i18n 大量 “Cyrene” |
| 主题分裂 | `tokens.css` 深色粉紫 `--rb-*`；运行主题仅 `pearl-white`；设置页 `data-ui-theme="pearl-white"` |
| 样式巨石 | `settings.css` 12万+ 字符，多处重复定义 `.btn-primary` 等 |
| 无设计文档 | `docs/` 下无 UI/视觉规范，改界面靠经验 |
| 文案未统一 | 设置导航/说明混用 Cyrene、昔涟、角色名 |
| 结构可沿用 | 设置分区、表单行、面板骨架合理，**可保留信息架构，换品牌与视觉** |

结论：**信息架构可继承，品牌与视觉必须收敛到本规范。**

## 3. 设计原则

1. **生命感优先**：界面服务于「她在这里」，而不是工具面板堆砌。  
2. **四模式一致**：Chat/Work/Code/Learn 共用同一套组件与品牌语，不各画一套。  
3. **单一体验主题（当前）**：`pearl-white` 为唯一正式主题；暗色等后续再开，不在业务代码里散落第二套色板。  
4. **组件复用**：新界面优先用 §5 组件；禁止再复制粘贴一份 form-row 样式。  
5. **可访问**：对比度、焦点态、键盘可达；勿仅用颜色表达状态。  
6. **中文优先文案**：用户可见字符串进 i18n；禁写死英文品牌。

## 4. 视觉 Token（pearl-white）

以 `src/renderer/ui/tokens.css` + 主题为准；业务 CSS **只引用变量**，不写死色值。

### 4.1 色彩（方向）

| Token 用途 | 建议语义 | 说明 |
|---|---|---|
| 背景 | 浅层白/灰白 | `pearl-white` 底 |
| 主文字 / 次要文字 / 弱文字 | 三级灰阶 | 对比度 ≥ 4.5:1（正文） |
| 品牌主色 | 待产品拍板后锁定 1 色 | 全应用同一主色（按钮/选中/焦点） |
| 成功 / 警告 / 危险 / 信息 | 状态色 | 仅用于状态，不作装饰大面积色块 |
| 描边 | 细边框 | 面板、输入框 |

> 当前 `tokens.css` 中 `--rb-*` 深色粉紫体系 **标记为 legacy**，新代码不得依赖；迁移期允许读取但禁止新增。

### 4.2 字体

- UI：`fonts.css` 系统栈（Microsoft YaHei / PingFang 等）  
- 代码块：等宽字体  
- 字号阶梯（建议）：12 / 13 / 14 / 16 / 18 / 22，避免随意 px  

### 4.3 间距与圆角

- 间距基数 **4px**：4 / 8 / 12 / 16 / 24 / 32  
- 控件高度：输入与按钮对齐（约 32–36px）  
- 圆角：控件 8px，卡片 12px，与窗口圆角设置协调  

### 4.4 图标

- 设置导航：线性 SVG，18px，currentColor  
- 状态：成功/失败用图标+文案，不单靠颜色

## 5. 布局与组件

### 5.1 设置页信息架构（现行分类）

```text
模型与智能
  模型服务          ← 厂商 / API Key（主配置）
  AI 引擎           ← Hermes：路径、端口、密钥、模型同步
  高级设置
  Token 用量
角色与体验
  角色与风格 · 记忆 · 外观 · 偏好
语音
  语音合成 · 语音识别
连接与工具
  消息渠道 · 工具配置 · 技能管理 · 代码辅助
数据与任务
  备份管理 · 定时任务
其他
  通用 · 用户 · 免责
```

新面板必须：左侧 nav 一项 + `data-panel` + `settings-section` 结构 + sticky 保存条。

**样式分层**：

| 文件 | 职责 |
|---|---|
| `ui/theme.css` | pearl-white + `--ui-*` / `--brand-*` 语义 token |
| `settings/styles/controls.css` | 按钮/表单/开关/分区等通用控件（新代码只引用这里） |
| `settings/<module>/*.css` | 各面板专属样式 |
| `settings.css` | 历史样式，**禁止再膨胀**；渐进迁出到上表 |

### 5.2 组件清单（新 UI 必用）

| 组件 | 用法 |
|---|---|
| `.nav-item` | 设置导航 |
| `.settings-panel` / `.settings-section` | 面板与分组 |
| `.form-row` / `.form-label` / `.form-control` / `.form-hint` | 表单 |
| `.toggle-switch` | 开关 |
| `.btn-primary` / `.btn-secondary` | 主/次操作（主按钮每面板仅一个） |
| `.save-status` | 保存反馈 |
| `.modal` | 确认与编辑弹窗 |
| Toast / showModal | 与现有 `shared/modal` 一致 |

### 5.3 聊天与桌宠窗

- 气泡、工具卡片、审批卡片：同一圆角与状态色  
- Live2D 窗：透出、不抢焦点；与设置窗视觉分离但品牌一致  
- React 聊天（`src/renderer/react`）：新功能优先落在已有组件树，避免旁路 HTML

## 6. 文案规范

| 场景 | 规范 |
|---|---|
| 产品名 | 使用拍板后的【产品名】，不用 Cyrene |
| 层名 | 智核 / 心核 / 壳 |
| 设置标题 | 「模块 + 短说明」；说明句 ≤ 40 字 |
| 错误 | 说清原因 + 下一步（如「Gateway 未启动，请在智核页检查」） |
| i18n | `zh-CN` 为源语言，键名稳定；`en-US` 同步 |
| 禁止 | 「CyreneHarness」等上游术语直接暴露给用户 |

## 7. 开发规范（UI 相关）

1. **新样式**：进模块目录（如 `settings/hermes/`）或抽公共组件；**禁止**继续膨胀 `settings.css` 无归属区块。  
2. **颜色**：只使用 theme token；禁止业务文件新增魔法色值（调试除外，合入前改回）。  
3. **状态**：加载/空/错误三态齐全。  
4. **交互**：破坏性操作确认；保存成功可见反馈。  
5. **命名**：DOM `id`/`data-*` 用英文 kebab-case；i18n 键 `模块.字段`。  
6. **验收**：改 UI 后至少 `npm run dev` 手工过一遍对应面板；涉及设置 IPC 需保存→重开仍在。  
7. **品牌改动**：改字符串先改 i18n，再改 `package.json` / `electron-builder.yml` / 标题。

## 8. 品牌与 UI 收敛计划（已开发部分）

| 优先级 | 动作 | 状态 |
|---|---|---|
| P0 | 产品名/智核名拍板 | **待用户选择** |
| P0 | i18n / 设置标题去 Cyrene → 产品名 | 待做 |
| P0 | 设置页「大脑 Hermes」→「智核」 | 待做（名定后） |
| P1 | `package.json` name/description、`productName`、appId | 待做 |
| P1 | README / 窗口标题 / 托盘文案 | 待做 |
| P2 | tokens：锁定 pearl-white 品牌色；标记 `--rb-*` legacy | 文档已定，代码渐进 |
| P2 | 拆分 `settings.css` 超大文件（按面板抽文件） | 渐进 |
| P3 | 聊天/桌宠窗视觉与设置页对齐 | 随 P1/P2 |
| P3 | 暗色主题（若要做） | 单独立项，不混业务 |

代码标识符（如 `cyrene-agent.ts` 文件名）可晚于 UI 文案迁移，但 **用户可见层必须先改完**。
